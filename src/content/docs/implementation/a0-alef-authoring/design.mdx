A0 is the first Florete release: a rete run by one operator, with no agent and no coordinator on any node. This page is its design, written as a delta on [C0](/docs/implementation/c0-tended-tunnels) — where A0 behaves as C0 does, it says so and links there, and it describes only what differs ([DSGN-A0-01](#decision-log)). What A0 is for, and what it leaves out, is its [Scope](/docs/implementation/a0-alef-authoring/scope).

If you are implementing A0, the sections after the [Shape](#shape) follow a node through its life — running, installed, enrolled, changed — and then cover what holds across it: hosts with several nodes, validation, logging and names. If you are changing A0's design, start at the Shape and the [Decision Log](#decision-log). If you are operating an A0 rete, the commands and their order belong to the operator playbook and the user guide rather than to this page.

## Shape

**STRUCTURE**

```log
  subject     A0 as C0 narrowed — a rete whose only long-lived process is one
              flor-vertex per node, whose only operator tool is retectl on one
              workstation, and whose only channel between them is a couriered
              bundle

  components  retectl      init, id issue, validate, compile, issue-bundle —
                           offline in every command
              flor         install, uninstall, version, enroll — and no
                           activation command, systemd being that
                           interface
              flor-vertex  the node's network proxy
              one release version over every executable, retectl included on
              every node

  supervisor  the systemd user manager
              unit       flor@.service in ~/.config/systemd/user/, a template
                         named for the scope rather than for what runs under it
              instance   systemctl --user enable --now flor@<node>.<rete>,
                         run by the operator; nothing is rendered per scope
              exec       flor-vertex --scope %i and nothing else — no FLORWL_*
                         is injected, and none is read
              policy     Restart=on-failure, RestartPreventExitStatus=78

  scope root  <state-dir>/retes/<node>.<rete>/, narrowed from C0
              receipt.json  same as C0
              scope.lock    the scope's exclusive lock, held by flor-vertex for
                            its life and by flor enroll for its run
              identity/     same as C0
              artifacts/    mgmt/<vertex>.json, written in place by enroll
              no other files and dirs of C0

  bundle      same as C0

  operator    same `~/.retectl` as C0, except no config.toml

  dev env     processes run directly, with no service manager
              several nodes of one rete on one host are several scopes, each
              <node>.<rete>, told apart by the listen addresses in their YAMLs
              each hand-run process logs to its own stderr
```

**FLOW**

```log
  install &   follows C0 process
  upgrade

  genesis     once per rete
                1  create the repo, then retectl init <name> inside it
                2  seed the collections; declare the nodes, services and users
                3  retectl compile, then commit
                4  from here it is an ordinary enrollment, per node

  enroll      follows C0 process with changes
                 no publish
                 manual activation/deactivation by systemd unit
                 artifacts go straight to artifacts/

  rollout     a change to any node's state is that node's re-enrollment, and
              there is no other channel
                1  edit YAML, retectl validate, retectl compile, read the diff
                2  commit
                3  issue-bundle every node the compile touched
                4  courier, stop, enroll, start — per node
              the fleet does not converge on its own; the operator walks it

  revocation  1  remove the principal from YAML
              2  retectl compile, then commit
              3  re-enroll every node whose set the removal touched
              a live key opens nothing once the last of those nodes is done
```

**RULES**

```log
  narrowing     A0 removes mechanisms, never rules

  verification  same as C0 except envelope signatures: they're not checked at node

  channels      one mgmt channel, the couriered bundle, applied by enroll

  freshness     no high-water-mark and no monotonicity check: enroll applies the
                set it was handed
                artifacts still carry the node's set version, stamped by the
                compiler against the committed tree
                the commit is the gate on issue-bundle

  partiality    material without an artifact is inert, and every revocation
                leaves some behind
                an artifact without material is degraded, and in A0 a defect
                rather than a state, one bundle carrying both planes; the
                vertex's warning is where it surfaces

  ownership     install owns the host, the vertex owns the scope while it runs,
                and enroll is the one act that crosses between them
                enroll refuses a live scope rather than quieting it, naming the
                holder and the systemctl stop that clears the vertex's one

  locking       same as C0, with flor-vertex in the agent's place: it holds
                its scope's lock for its life, and exits 69 when it finds the
                lock held

  activation    enroll activates nothing, and A0 doesn't abstract activation:
                the operator instantiates the unit through the systemd
                a scope surviving an uninstall is enrolled-but-inactive, and
                resumes with no bundle and no re-issue

  paths         artifacts carry no filesystem references
                the vertex derives its paths from the scope alone, and its own
                name from the artifact it finds there

  logging       every process opens its own log sink from configuration
                the class is what a process opened, and nothing may say otherwise
                a destination absent, unreachable or of the wrong socket type
                stops the process rather than degrading it
                every record is framed flor-<workload> and carries its scope as
                node and rete, written by the formatter
                flor's commands log to syslog, retectl to stderr and off unless
                asked
                no counters and no flood-safe Layer: events carry closed values
                as fields, and the journal's per-unit rate limit is the flood
                bound

  platforms     Linux with systemd on x86_64, user mode only
```

## A node without an agent

An A0 node runs one long-lived process, `flor-vertex`, and nothing supervises it but systemd. The installer places a single template unit, `flor@.service`, among the user's units, and the operator starts a scope with `systemctl --user enable --now flor@<node>.<rete>` and takes it down with `stop` or `disable`. `flor` has no command for this: activation in A0 is the service manager's, and the user guide teaches its commands ([DSGN-A0-08](#decision-log)). systemd restarts the vertex when it fails, except on exit `78`, which says the scope cannot be served as it stands.

The unit tells the vertex one thing, its scope — `flor-vertex --scope %i` — and the vertex works out the rest ([DSGN-A0-09](#decision-log), [DSGN-A0-10](#decision-log)). It takes its scope's lock exclusively and holds it while it runs, exiting `69` when another process holds it. It reads `receipt.json` and refuses a scope that was never enrolled, is mid-enrollment, or was written by a release it cannot read. It opens the one artifact under `artifacts/mgmt/`, refusing a scope root that holds more than one, takes its own name from that artifact's envelope, and derives every path it needs from the scope. No `FLORWL_*` variable is set or read. These are jobs C0 gives the agent, and in A0 they are the vertex's.

What a node holds follows from the same absence. The scope root is C0's without what the agent owns, the artifact sitting directly at `artifacts/mgmt/<vertex>.json` ([DSGN-A0-11](#decision-log)). The compiler emits no `agent.json`, the bundle carries no node principal, and nothing is created in the runtime directory ([DSGN-A0-02](#decision-log)). A node's identity is its name as the manifest states it, pinned in `identity/scope.json`.

The vertex serves every principal it holds material for, as in C0. In A0 a principal named without its material is a producer's mistake rather than a passing state, and the vertex's warning is where it shows ([DSGN-A0-05](#decision-log)).

## Installing

A0 installs, upgrades and uninstalls as [C0's installer](/docs/implementation/c0-tended-tunnels/installer) does, in one mode on one platform: user mode, on x86_64 Linux with systemd ([DSGN-A0-07](#decision-log)). What exists only for another mode or another platform is not part of A0.

An upgrade stops the active units before it swaps files and starts them after, as C0's does. Nothing keeps a vertex from being started, or an enroll from being run, while the swap is under way; that is the operator's to avoid, as under any package manager ([INST-C0-03](/docs/implementation/c0-tended-tunnels/installer#decision-log)).

A plain uninstall leaves each scope root in place, enrolled but inactive. After a reinstall, enabling the unit is all a scope needs — no bundle, no re-issue.

## Enrolling and changing a node

A rete begins as it does in C0 — a repository, `retectl init`, the collections, a compile and a commit — with nothing that has to exist first: there is no management node to bootstrap and nothing to publish to. Every node then joins by an ordinary enrollment.

Enrollment follows [C0's](/docs/implementation/c0-tended-tunnels/mgmt-plane/enrollment), and the differences are few. It verifies the bundle as C0 does, and checks no artifact's signature — nothing on an A0 node does ([DSGN-A0-03](#decision-log)). It writes the artifact straight to its place instead of leaving it for an intake. And it activates nothing: its last line is the `systemctl` command that starts the scope, and on a live scope it refuses, naming the holder and the `systemctl` command that stops it (in case it is a vertex).

Artifacts are signed when compiled and carry the node's set version, and `retectl issue-bundle` refuses an uncommitted tree ([DSGN-A0-04](#decision-log)). No A0 node compares versions: enroll applies the set it is handed.

A0 changes a node in one way, by re-enrolling it ([DSGN-A0-06](#decision-log)). A change is compiled and committed, and every node it touched receives a fresh bundle — carried out of band, the scope stopped, the bundle enrolled, the scope started — which re-mints every principal on that node. There is no `publish` and nothing syncs, so the rete converges as fast as the operator walks it. Revoking a principal is removing it from YAML and re-enrolling the nodes whose sets named it, taking effect node by node on the same walk. `retectl` is offline throughout, and has no `config.toml`.

## Several nodes on one host

A host can hold several nodes of one rete, as in C0: each is its own scope, `retes/<node>.<rete>/`, and enrolling the second takes `--multi-node` ([ENRL-C0-41](/docs/implementation/c0-tended-tunnels/mgmt-plane/enrollment#decision-log)). In A0 each also runs under its own unit, `flor@<node>.<rete>`.

The development environment is that arrangement run by hand ([DSGN-A0-15](#decision-log)). Its processes start from scripts, terminals or a process manager, with no service manager involved — on Linux, and on macOS once C0 targets it. Its nodes are told apart by the loopback addresses their YAML declares, and each logs to its own stderr. `FLOR_STATE_HOME` is a convenience there, never the way nodes are kept apart. Where a development node needs more than its YAML can say, that is the node-local override [ENRL-C0-04](/docs/implementation/c0-tended-tunnels/mgmt-plane/enrollment#decision-log) reserves.

## Validating a rete without a coordinator

A rete has a management node when it declares both reserved coordinator services, and only then do the rules requiring a management node and a user holding `operator` apply ([DSGN-A0-13](#decision-log)). An A0 rete declares neither; declaring exactly one is an error naming the other. The reserved names — the two services, their groups, and the `node` and `operator` roles — are reserved in every rete whether it uses them or not, and `retectl init` writes them into a new rete commented out. Otherwise A0 validates as [C0](/docs/implementation/c0-tended-tunnels/mgmt-plane/validate-and-compile) does.

## Logging

Every A0 process opens its own log sink ([DSGN-A0-16](#decision-log)). It reads the destination from configuration, connects the syslog socket itself, and takes its class from what it opened; nothing provisions a sink for another process, and `FLORWL_LOG_SINK` is not read. A destination that is absent, unreachable or of the wrong kind stops the process with `69` or `78` rather than sending its records elsewhere. Commands log as C0's do, and `retectl` writes to stderr only when asked.

Each record says which process wrote it and which scope it belongs to ([DSGN-A0-17](#decision-log)). The syslog identifier is `flor-<workload>` — the vertex's, in A0 — and the formatter writes `scope{node=… rete=…}` at the head of every line. Under systemd, `journalctl --user-unit flor@<node>.<rete>` selects a scope and `-t flor-<workload>` a process within it; where no unit is recorded, the line's own scope says which scope wrote it.

The line format and its vocabulary are [C0's](/docs/implementation/c0-tended-tunnels/observability), without the counters and without the flood-safe Layer ([DSGN-A0-18](#decision-log)). Events are written so both can be added without touching them: each event C0 will count carries its bounded values as fields, with a closed `reason`, and each event a peer can trigger at will is a `tracing` event with fields. A flood is bounded by the journal's per-unit rate limit, and a count of denials is a count of log lines.

## Names

A supervised workload is named `workload/<node>/<name>`, and the supervisor `workload/<node>/agent`, as [Identity](/docs/implementation/c0-tended-tunnels/mgmt-plane/identity#decision-log) decides (ID-C0-09); a vertex's workload takes the vertex's declared name, and that is what an artifact's node and name address. A0 supervises nothing, yet its compiler names the vertex's artifact and its log frames the vertex's records by this naming.

The vertex's configuration lists the TLS principals it terminates mTLS for as its `attachments`, the principals attached to the vertex from above ([DSGN-A0-20](#decision-log)).

## From A0 to C0

A node moves to C0 by installing C0 and re-enrolling with a fresh bundle, and nothing is migrated ([DSGN-A0-21](#decision-log)). Every part of a C0 scope root that A0 lacks comes from C0's agent or from the bundle. A0's artifact file stays behind, inert, unless the scope root is removed first.

## Decision Log

Entries are grouped by what a change would touch.

### The page

**DSGN-A0-01. Record A0 as a delta on C0.**
This page states what A0 does differently and cites C0 for the rest: where A0 follows a C0 process it says so and names only the difference. Where A0 gives the vertex or enroll a job C0 gives the agent, the job is A0's alone, and the entries do not restate what C0 does instead. One page carries the whole delta.
*Because* A0 is C0 with its agent and coordinator removed, so nearly every mechanism A0 keeps is C0's unchanged, and a restated process — or a restated C0 alternative — is a second copy that drifts from the first.
*Accepting* that the page is not read alone, and that a change to a cited C0 process changes A0 unless an entry here says otherwise.
*Rejected* a self-contained A0 design, which duplicates the pages it would have to track; splitting the delta by component as C0 is split, which divides something its reader wants in one read; amending the C0 records with A0 clauses, since C0's log describes C0; ending each entry with what C0 does instead, a clause that restates C0 and goes stale with it.

### What the absent agent and coordinator leave

**DSGN-A0-02. Emit no `agent.json`, mint no node principal, and create no runtime root.**
A node's mgmt set is its vertex's artifact alone; the bundle carries user and service principals and no `node/<name>`; nothing is created in the runtime directory. A node's identity is the manifest's `node` claim, pinned in `identity/scope.json`.
*Because* each exists for the agent: `agent.json` carries a supervision inventory, a sync block and an endpoint map for `agent.sock`; the node principal authenticates the agent to the coordinator; the runtime root holds `agent.sock`. A0 has neither end of any of them.
*Accepting* that the set has no root document, its coherence being the bundle's; and that expiry is warned by whatever touches a certificate ([ID-C0-23](/docs/implementation/c0-tended-tunnels/mgmt-plane/identity#decision-log)).
*Rejected* a reduced or empty `agent.json`, an artifact the compiler keeps filling for no reader; a node principal minted and unused, a ninety-day bearer credential couriered for nothing and minted afresh at C0's re-enrollment (DSGN-A0-21); an empty runtime root, a mode rule and a cleanup path for a directory holding nothing.

**DSGN-A0-03. Sign every artifact, and verify no envelope on the node.**
`retectl compile` signs each envelope as C0 does, and the validator's mgmt-signer rule is C0's. `flor enroll` verifies a bundle as [ENRL-C0-17](/docs/implementation/c0-tended-tunnels/mgmt-plane/enrollment#decision-log) does and checks no envelope's signature, and nothing else on an A0 node does. On a re-enrollment the manifest's signature covers the artifacts through the digests it carries.
*Because* enroll is the act that makes a scope exist — it pins the anchors, the trust domain and the node, and nothing else may — while checking an envelope's signature is admission, a judgement about authority over rete state repeated at every arrival. [ADR-0015](/docs/implementation/adr/0015-anchor-signer-trust-in-root-ca) makes the agent the sole verifier, and admission lent to enroll would be a boundary drawn in the wrong place.
*Because* the check would add nothing A0 lacks: the manifest's signature authenticates what a re-enrollment carries, a fresh enrollment verifies no signature at all, and whoever can write an artifact at rest can write the identity material beside it.
*Because* signing costs nothing extra: the envelope contract requires a signature, and the signer, the key handling and the canonical form serve the manifest regardless.
*Accepting* envelope signatures nobody on an A0 node consumes, so their envelope-specific part is first exercised by whatever verifies them later, the signer and the canonical form being exercised by every manifest meanwhile.
*Rejected* verifying envelopes at enroll, a second verifier for what the manifest already establishes; unsigned artifacts, an unsigned form of a contract that requires a signature.

**DSGN-A0-04. Stamp set versions and gate bundles on the commit, with no high-water-mark.**
The compiler stamps each node's set version against the committed tree, and `retectl issue-bundle` refuses an uncommitted tree, as [ENRL-C0-35](/docs/implementation/c0-tended-tunnels/mgmt-plane/enrollment#decision-log) decides. Enroll applies the set it is handed, with no monotonicity check.
*Because* the version is part of the envelope's routing core, so dropping it would change the contract rather than narrow it; and the commit keeps the compiled tree an honest record of what each node was given.
*Accepting* a version nothing on an A0 node reads.
*Rejected* dropping the version, a contract change; a monotonicity check at enroll, a high-water-mark under another name; a warning in place of the commit gate, which a courier's delay separates from the harm it warns about.

**DSGN-A0-05. Keep C0's handling of an artifact without its material, as a defect rather than a state.**
The vertex serves every principal it holds material for, opens no listener for one it does not, and warns once, as [ENRL-C0-36](/docs/implementation/c0-tended-tunnels/mgmt-plane/enrollment#decision-log) decides. In A0 the state arises only from a producer's mistake.
*Because* A0 has one channel, and its bundle carries each principal's material together with the set naming it.
*Rejected* refusing such a set, which lets the identity store veto the set.

**DSGN-A0-06. Roll out by re-enrollment, with no `publish`.**
Every change to a node's state reaches it in a fresh bundle — compile, commit, issue, courier, stop, enroll, start — and re-mints every principal on the node. `retectl` ships `init`, `id issue`, `validate`, `compile` and `issue-bundle`, all offline, with no `publish`, no `config.toml` and no path into flor.
*Because* A0 has no coordinator to publish to or sync from, and a command that exists is a promise.
*Accepting* that the fleet converges as fast as the operator walks it, and that a revocation takes effect node by node on the same walk.
*Rejected* a `publish` that refuses; calling the courier step a publish, which names a mechanism A0 does not have.

### Installation and supervision

**DSGN-A0-07. Install, upgrade and uninstall as C0 does, in user mode only.**
A0 follows [C0's installer](/docs/implementation/c0-tended-tunnels/installer) — and leaves out what only a second mode, platform or moving default needs: system mode and its service user, mode detection, macOS and its per-scope wrappers, the upgrade step re-rendering them, the side-by-side configuration file, and every directory override but the state directory's.
*Because* each part is kept by whether A0 has the situation it exists for: dogfooding upgrades nodes often, a crash between stopping and restarting units must not lose which scopes were active, and a hand-built binary in the install prefix is what the ownership refusal protects.
*Accepting* that A0's installer is a program, not a script.
*Rejected* a receipt without its phase and previous release, which loses the active scopes across a crash and the way back; unpacking over the top, which loses both; a `--system` that refuses, a flag promising what A0 does not ship.

**DSGN-A0-08. Supervise the vertex with an installer-authored systemd template, and give `flor` no activation command.**
The installer places `flor@.service` in the user manager's unit directory — one template, named for the scope rather than for what runs under it — and nothing renders a unit per scope. The operator activates a scope with `systemctl --user enable --now flor@<node>.<rete>`; enroll prints that line, and its refusal of a live scope names the holder and the matching `stop`.
*Because* only the installer can refresh every scope's supervision when a release changes the unit, and a unit named for its process would need renaming once a supervisor runs under it instead.
*Because* an activation command would abstract one service manager on one platform, named before C0 settles what it activates.
*Accepting* that A0's documentation names systemd, A0 having no activation abstraction to keep neutral; and that its user guide teaches commands a later activation command replaces.
*Rejected* `flor-vertex@.service`, which a supervisor's arrival replaces instance by instance; a unit rendered by enroll or written by the operator, a second author of supervision; `flor enable`, `flor scope enable`, `flor agent enable` and `flor vertex enable`, each naming an act A0 does not abstract.

**DSGN-A0-09. Pass the vertex its scope, and nothing else.**
The unit runs `flor-vertex --scope %i`. The vertex opens its set's one artifact, takes its own name from that envelope, and derives every path from the scope; the unit sets no `Environment=`, and the vertex reads no `FLORWL_*`. `--name` is an optional override. Wherever a command takes a scope, the flag is `--scope`.
*Because* a systemd template has one instance parameter, spent on the scope, and neither the installer, which knows the layout but not the vertex's name, nor enroll, which knows the name but would render a unit per scope, can supply more.
*Because* the `FLORWL_*` variables describe a supervised workload, and A0 supervises nothing.
*Because* the value is a scope handle rather than a rete name ([ENRL-C0-41](/docs/implementation/c0-tended-tunnels/mgmt-plane/enrollment#decision-log)).
*Accepting* that the vertex's own lookup lasts only until a supervisor hands it its context; that the vertex refuses a scope root holding more than one artifact; and that path derivation stays in one module per holder, so a store that is not a file tree replaces one place.
*Rejected* an artifact path baked by the installer, which cannot know the vertex's name; paths built from systemd's own state-directory specifier, resolved against systemd's notion of the directory rather than flor's; a validator rule fixing the vertex's name, a YAML constraint made of a systemd limit; honouring `FLORWL_*`, a consumer with no producer; `--rete`, the wrong one of the two names.

**DSGN-A0-10. Keep the receipt and the scope lock, with the vertex in the agent's place.**
`receipt.json` is C0's ([ENRL-C0-39](/docs/implementation/c0-tended-tunnels/mgmt-plane/enrollment#decision-log)). The scope lock is held by `flor-vertex` for its life and by `flor enroll` for its run, and enroll refuses a live scope rather than stopping it, naming the holder. A vertex that finds the lock held exits `69`. Before serving, the vertex refuses a scope whose receipt is absent, reads `enrolling`, or carries a schema version it cannot read, exiting `78`.
*Because* what the two guard — an interrupted enrollment, and a process reading the identity plane while enroll rewrites it — does not depend on the agent, and in A0 the vertex is that process.
*Because* a held lock is held by an enroll or another vertex, which ends, so the vertex refuses it as a condition that may resolve rather than as a scope it cannot serve.
*Accepting* that the lock and the receipt check live in the vertex only until a supervisor holds the scope, and move to it unchanged.
*Rejected* deciding whether an enrollment finished from the identity store, which is written before the commit point; a lock only enroll takes, which excludes no live reader; asking systemd whether the unit is active, a read outside any lock; checking the receipt at an activation step, which a reboot bypasses.

**DSGN-A0-11. Write artifacts in place.**
Enroll writes each artifact to `artifacts/mgmt/<vertex>.json`, its destination read out of its own envelope. There is no `incoming/`, no intake, no `current` pointer and no `sets/`.
*Because* `incoming/` serves an intake that is the agent's, and the pointer replaces a set under a running consumer; A0 has neither, and enroll never writes under a live vertex (DSGN-A0-10).
*Accepting* that no previous set is kept on the node, rollback being a reverted, recompiled and re-enrolled one; and that enroll writes through the library an intake would use, so adding one changes the caller rather than the code.
*Rejected* an `incoming/` admitted by the vertex, which makes the network proxy a verifier; the versioned tree and its pointer, atomicity nothing needs, taught to a vertex with no use for it.

### Validation

**DSGN-A0-13. Apply the management-node rules only where the reserved coordinator services are declared.**
Where `coordinator` and `coordinator-publisher` are both declared, the rules requiring a management node and a user holding `operator` apply; where neither is, they do not; where exactly one is, validation fails naming the other. The reserved names — those services, their groups, and the `node` and `operator` roles — are reserved either way and required only with a management node, and `retectl init` scaffolds them commented out. `rete.yaml` is C0's.
*Because* a rete's shape is read from what it declares, and a trigger one typo could switch off would be worse than none: mistyping one of the two names lands in the failing case.
*Because* a rete that later grows a coordinator must not find its names taken.
*Accepting* that A0's operator is an ordinary user holding no role, and that `node` and `operator` have no members.
*Rejected* a declaration in `rete.yaml`, which copies a reserved name into authored source; a profile switch on the command line, which makes a rete's shape depend on who validates it; a separate A0 rule set; releasing the reserved names.

### Scopes and hosts

**DSGN-A0-15. Run the development environment without a service manager.**
Development processes are started directly — by scripts, terminals or a process manager — on Linux, and on macOS once C0 targets it. Several nodes of one rete on one host are several scopes ([ENRL-C0-41](/docs/implementation/c0-tended-tunnels/mgmt-plane/enrollment#decision-log)), told apart by the loopback addresses their YAML declares, and each hand-run process logs to its own stderr. `FLOR_STATE_HOME` is a convenience, never the mechanism.
*Because* the test environment — one node per host, over the Internet — runs the unit, the installer and enrollment as they ship, and a development environment tied to systemd could not be the same one on a Mac.
*Accepting* that no development machine exercises the unit file; and that the development environment will need node-local overrides beyond what its YAML says, which are for the override [ENRL-C0-04](/docs/implementation/c0-tended-tunnels/mgmt-plane/enrollment#decision-log) reserves to provide.
*Rejected* development on the shipped unit, which ties it to one platform's service manager; both, selectable, two environments for one team; designing node-local overrides here.

### Logging

**DSGN-A0-16. Let every process open its own log sink, and stop on a bad destination.**
Each flor process resolves its log destination from configuration and connects the syslog datagram socket itself. A process's sink class is the one it opened — a socket is `syslog`, stderr is `private` — and `FLORWL_LOG_SINK` is not read. An absent or unreachable destination exits `69` and a stream socket exits `78`; the vertex never falls back to stderr. Commands log as C0's do.
*Because* [ADR-0014](/docs/implementation/adr/0014-provision-log-sinks) decides that a log sink is a connected datagram socket and that a supervisor provisions it for its children; A0 has no children, so the second half is dormant and the first stands.
*Because* systemd cannot hand a process a connected datagram socket as its stderr: its syslog output is the journal's line-splitting stream, and its file output connects a stream socket.
*Because* A0's logs are what an evaluation of A0 reads, and a vertex running without them runs unaccountably.
*Accepting* a larger blast radius than a supervisor's refusal would have, a logging outage at start taking forwarding with it; and that two hand-run vertices writing one redirected file carry no workload names.
*Rejected* the journal's stdout stream, which splits a multi-line record into one entry per line; a wrapper that provisions, a supervisor in all but name; honouring `FLORWL_LOG_SINK`, which could only contradict the socket a process holds; falling back to stderr.

**DSGN-A0-17. Frame records as `flor-<workload>`, and write the scope into every record.**
The syslog identifier is `flor-<workload>` — `flor-agent` for the supervisor, `flor` for the commands, and nothing of flor's for a tenant workload. The formatter writes `scope{node=… rete=…}` ahead of the span stack on every line, from values set when logging starts; the scope never enters the identifier.
*Because* the journal attributes a record to its sender's unit, and every process a supervisor forks shares the supervisor's unit, so the unit tells scopes apart and the identifier has to tell processes apart.
*Because* every program on a host shares the identifier space, where a bare workload name is ambiguous; the prefix keeps flor's records its own, as `flor_` does for metrics.
*Because* where no unit attributes a record — a plain syslog file, a process run by hand — the content is the only place the scope can be, and a span entered at start never reaches events emitted by asynchronous tasks.
*Because* `node` and `rete` are the resource-identity tokens of [C0's observability](/docs/implementation/c0-tended-tunnels/observability), `node` naming the bare node, so a line carries all three with the workload in the identifier.
*Accepting* that both attributions inside a record are the process's own claim, the unit being the trusted one where there is one; that the scope looks like a span without being one; and that a long vertex name makes a long identifier, which some daemons cut at 32 characters.
*Rejected* the bare workload name; the executable name, which C1's two vertices share; the scope in the identifier, which a length cap cuts where the identifier is the only attribution; adding the scope only where no unit seems to attribute the record, an inference from surroundings; leaving the scope to C0, which changes the line format after operators depend on it.

**DSGN-A0-18. Build no counters and no flood-safe Layer, and keep event sites ready for both.**
Every event C0 will count carries its bounded values as `tracing` fields in C0's vocabulary, with a `reason` that is a closed value rather than a formatted error, and every flood-prone event is a `tracing` event with fields. A0 builds no counter registry and declares no dependency on one.
*Because* [C0's counters](/docs/implementation/c0-tended-tunnels/observability) are explicit calls at the event site, needing only closed values there, and the flood-safe Layer is one module keyed by call site and one field — so both are additions, and no site is rewritten.
*Because* a registry injected later costs a dependency on the components that count, and the vertex is the only code in A0 that will.
*Accepting* that A0's flood bound is the journal's per-unit rate limit, which drops records indiscriminately while a flood lasts; and that A0 counts denials by counting log lines.
*Rejected* the Layer alone, the half that is cheap to add later; counters with no readout, a surface nobody reads before monitoring exists; counters derived from events, which have no event for a byte or a retried attempt and make every counted event part of a metric; an ambient registry, global state every counting test must reset.

### Naming

**DSGN-A0-20. Call the TLS principals a vertex serves its `attachments`.**
The vertex payload lists the principals the vertex terminates mTLS for as `attachments`.
*Because* a vertex is a point of attachment, where a layer's users attach, and the word names that relation rather than a credential — holding in C1, where a mesh vertex attaches to a link vertex in the same sense.
*Because* *workload* names a supervised process ([ID-C0-09](/docs/implementation/c0-tended-tunnels/mgmt-plane/identity#decision-log)), and a payload field's name lasts as long as its major version.
*Rejected* `workloads`, one word for two things on one node; `tls_principals`, ambiguous in C1 where a mesh vertex is itself a TLS principal; settling the name at C0, a major version for the same result.

### Forward

**DSGN-A0-21. Move a node from A0 to C0 by re-enrollment, migrating nothing.**
Installing C0 and re-enrolling each node with a fresh bundle is the whole step: every part of a C0 scope root that A0 lacks is created by C0's agent or delivered in the bundle. A0's artifact file stays beside C0's set tree, inert, unless the operator removes the scope root first.
*Because* re-enrollment is already A0's only way to change a node.
*Accepting* one leftover file per scope.
*Rejected* migrating A0 scope roots in C0's agent, a mechanism for a step that already exists.
